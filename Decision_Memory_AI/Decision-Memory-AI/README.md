# Decision Memory AI 🧠

An autonomous GitLab skill that intercepts merge requests, extracts the architectural "Why" via the discussion thread, and makes it semantically searchable for the whole team.

*Built for the [GitLab Transcend Hackathon](https://gitlab-transcend.devpost.com/) (Showcase Track)*.

## 🚀 The Problem

We've all been there: staring at a legacy codebase or a complex Merge Request, wondering *why* a specific caching layer was chosen or *why* a component was refactored. The "what" and "how" are in the code, but the "why" is lost in ephemeral Slack messages or developer brains. 

We wanted to capture these fleeting architectural decisions effortlessly **without burdening developers with heavy documentation processes.**

## 💡 The Solution

**Decision Memory AI** acts as a silent team member that hooks directly into your GitLab repository:

1. **Listens:** It monitors Merge Request webhooks (opens, updates, and comments).
2. **Understands:** It uses Cohere's `command-r-plus` model to analyze the MR description, commits, and the **Discussion Thread**.
3. **Interacts:** If the developer didn't provide enough context, the AI dynamically generates a context-aware question based on the files changed and posts it back into the GitLab MR comments! 
4. **Remembers:** Once the decision is extracted, it stores the summary, reasoning, and a confidence score in a `pgvector` database.
5. **Retrieves:** Developers can use the companion UI to perform semantic searches (e.g., *"Why did we use Redis?"*) and instantly get a generated answer with citations pointing to the exact MRs.

## 🛠️ Tech Stack

- **Backend:** Node.js, Express
- **Database:** PostgreSQL with `pgvector` / SQLite for semantic embeddings
- **AI/LLM:** Cohere `command-r-plus-08-2024` for reasoning and extraction
- **Frontend:** React, Vite, TailwindCSS
- **Infrastructure:** Docker Compose, Ngrok, GitLab Webhooks

## 💻 Local Setup Instructions

If you want to run this project locally to test the webhook interactions, follow these steps.

### Prerequisites
- Docker and Docker Compose (or local Node.js)
- Node.js (v18+) & npm
- [Ngrok](https://ngrok.com/) installed
- A [Cohere API Key](https://dashboard.cohere.com/)
- A GitLab Personal Access Token (with `api` scope)

### 1. Clone & Configure
Clone the repository and set up your environment variables.
```bash
git clone https://github.com/Dharshini-narayanan/Decision-Memory-AI.git
cd decision-memory-ai
```

Create a `.env` file in the root directory:
```ini
COHERE_API_KEY=your_cohere_api_key
GITLAB_URL=https://gitlab.com
GITLAB_TOKEN=your_gitlab_personal_access_token
DATABASE_URL=postgresql://postgres:postgres@db:5432/decision_memory
```

### 2. Start the Backend & Database
#### Option A: Docker Compose
Use Docker Compose to spin up the Node.js backend, PostgreSQL database, and frontend:
```bash
docker compose up -d --build
```
*The backend API will now be running on `http://localhost:8000`.*

#### Option B: Run Locally with Node.js
```bash
# In backend directory
cd backend
npm install
npm start   # or npm run dev
```

### 3. Expose the Webhook with Ngrok
GitLab needs a public URL to send webhook events to your local machine.
```bash
ngrok http 8000
```
Copy the forwarding URL generated by Ngrok (e.g., `https://1234abcd.ngrok-free.app`).

### 4. Configure GitLab Webhooks
1. Go to your GitLab Repository -> **Settings** -> **Webhooks**.
2. Add your Ngrok URL followed by the webhook path: `https://1234abcd.ngrok-free.app/webhook/gitlab`.
3. In the **Secret token** field, enter your `GITLAB_TOKEN`.
4. Under Triggers, select **Merge request events** and **Comments**.
5. Uncheck "Enable SSL verification" if Ngrok causes issues, and click **Add webhook**.

### 5. Start the Frontend UI
The React frontend is automatically built and started by Docker Compose on port `5173`.
*The UI will be available at `http://localhost:5173`.*

## 🧪 Testing the AI

1. Create a new branch and push a commit modifying a file (e.g., `cache_service.py`).
2. Open a Merge Request but leave the description blank or very vague.
3. Watch the GitLab MR! Within seconds, **Decision Memory AI** will comment on your MR asking a context-aware question about why you changed that file.
4. Reply to the bot with your reasoning (e.g., *"We switched to Redis for better performance"*).
5. The bot will silently read your comment, update its internal knowledge graph, and mark the decision as complete.
6. Go to `http://localhost:5173` and search *"Why did we switch to Redis?"* to see the AI cite your MR!
